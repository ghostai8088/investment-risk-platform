**The crux, verified:** the person-level SoD is a raw Python string comparison (`actor.actor_id in makers` / `in responders`) over free-text `String(255)` columns (`limit/service.py:506-514`, `limit/lifecycle.py:343-351`), while `has_permission` compares the same identity through a `GUID` column — on PG, case-INsensitive. So a non-canonical string form of the SAME principal **passes the entitlement gate but escapes the SoD set-membership** → self-approval. In OIDC mode `Principal.user_id` is already the server-resolved `app_user.id` (`deps.py:127-136`, canonical by construction) — the fix is cheap, but only if the slice mandates that identity space and closes the provisioning + dev-shim leaks.

## The demands (ranked; each with its proof test)

- **D1 (CRITICAL) — one actor-identity space, one canonicalization point, symmetric at stamp and compare.** Actor identity for SoD = `app_user.id` in canonical lowercase UUID text, ALL auth modes; ONE dependency constructs every `LimitActor`/`BreachActor` via `str(uuid.UUID(principal.user_id))` (the `deps.py:122` tenant idiom); no handler ever passes `claims.subject`/email/request-body as `actor_id`; the same canonical value feeds the audit actor + `checked_makers`. *Tests:* uppercase-form maker approving own draft under lowercase form → SoD-refused (today it would SUCCEED); two distinct principals don't falsely collide; OIDC end-to-end both directions.
- **D2 (CRITICAL) — identity-provisioning doctrine: one human = one live `app_user` row.** `(tenant_id, external_subject)` uniqueness is per SUBJECT-STRING, not per human (`entitlement/models.py:26-31`) — re-provisioning/IdP `sub` drift mints a second row and defeats the SoD invisibly. Ratify: rebind updates `external_subject` on the SAME row (never a sibling insert); deactivate-don't-delete; `sub` matched exactly (canonicalize by RESOLVING to `app_user.id`, never by normalizing the claim). *Test:* SoD holds across an `external_subject` rebind.
- **D3 (CRITICAL) — the API must not mint a second write path.** `status` is NOT a field on create/update DTOs (OpenAPI-asserted); suspend/resume/approve are dedicated endpoints onto the gated service fns; PATCH builds `**changes` from `exclude_unset` only; NO mutating verbs on breaches outside the four lifecycle transitions; handlers are thin pass-throughs (no direct ORM writes). *Tests:* status-smuggling into create yields DRAFT-or-422; the full MG-3 bypass suite (suspend→edit→resume; status+governing combo) replayed through HTTP.
- **D4 (HIGH) — the per-endpoint permission table + conformance test.** limit CRUD/suspend/resume=`limit.manage`; approve=`limit.approve`; reads=`limit.view`/`breach.view`; assign/review/close=`breach.review`; respond=`breach.respond`. Parametrized-over-routes 403 test; plus a `platform_admin` (holds ALL codes) still SoD-refused on own draft — the person-level check is the backstop for the admin dual-hat.
- **D5 (HIGH) — BR-15 human-only derived, not hardcoded.** `LimitActor.actor_type` DEFAULTS to `"user"` and routers hardcode it; nothing distinguishes a machine token. Decide: an `is_human`/`principal_type` marker on `app_user` threaded through `Principal`, or a ratified "app_user is human-only" doctrine + a provisioning prohibition (with the `acr`/`amr` MFA assertion as the upgrade path). A machine credential must have NO route to approve/review/close.
- **D6 (HIGH) — breach state in read models is recency-derived, never `Breach.status`.** The column is frozen at `DETECTED` (MG-2 deprecated-in-place); a DTO serializing the ORM row misreports forever. `state` = `current_breach_state` (batched — see D9). *Test:* assign+respond via services, GET reports RESPONDED while the column still says DETECTED.
- **D7 (HIGH) — exhaustive refusal map + double-submit semantics.** Map the DOMAIN classes (`LimitError`/`LimitSodError`/`BreachTransitionError`/`BreachSodError` → 422/the OQ-c status; not-found → 404 no-tenant-leak; unique-`IntegrityError` → 409) — never `ValueError` broadly; single end-of-request commit (AD-016; response built BEFORE commit — the txn-local GUC). *Tests:* two-session PG double-approve → clean refusal never 500; double-POSTed transition; SoD status pinned.
- **D8 (MED) — the P3-5 cross-tenant FK guard at every new write endpoint.** `create_schedule` STILL stamps caller-supplied `scope_portfolio_id`/`model_version_id` unresolved (`scheduling/service.py:279-315`) — the named carry is paid BEFORE its HTTP surface exists. Also: `assigned_to` on breach-assign is a free string — must resolve to an ACTIVE `app_user` in the acting tenant. *Test:* PG-tier cross-tenant id on every write endpoint → 404/422, never a stamped foreign FK.
- **D9 (MED) — reads through the existing seams.** New list-reads (limits-by-status/approval queue, breaches, action timeline) live in the shared package with the explicit tenant predicate atop RLS; governed-number touches go through `calc/reads`/the latest-resolvers (AD-019 — `limit_health` already complies, verified); batch the per-breach state derivation (do NOT replicate the `select_overdue_breaches` N+1 at HTTP list scale).
- **D10 (MED) — tick-only verbs stay tick-only.** No HTTP endpoint exposes `evaluate_limit`/`escalate_overdue_breach` (they synthesize SYSTEM actor ids — a user-triggered evaluate would forge the audit trail). On-demand evaluation = a NEW ratified decision, never a router convenience. Route-inventory test pins the exact verb set.

## Open questions for the slice-1 ratification gate

- **OQ-a — the worker's raw tenant string is the SSO-1 bug's SECOND instance, silent-FAIL-OPEN in effect (the audit's headline discovery).** `main()` feeds `--tenant`/`$IRP_TENANT_ID` RAW into `run_in_tenant`→`set_tenant_context` (`scheduler.py:161-177`) — a non-canonical (uppercase/braced) tenant id makes RLS hide every row: the tick fires ZERO schedules, evaluates ZERO limits, escalates NOTHING, and prints a normal-looking `fired=0` summary. For a monitoring control, silent-empty IS fail-open. **Demand: `str(uuid.UUID(...))` at the worker entry + a PG regression — in the API slice or cadence-wiring slice, as a named BLOCKING carry (latent only until infra invokes the tick).**
- **OQ-b** — dev-header mode must carry a canonical `app_user.id` and route through the SAME D1 dependency (the uppercase-defeat vector lives in the dev shim).
- **OQ-c** — HTTP status for a person-level SoD refusal: 403 (reads as entitlement — it is not) vs 409 (domain-state conflict). Pick one, uniform across `LimitSodError`/`BreachSodError`, pinned by test.
- **OQ-d** — `approval_ref` v1 contract at the edge (free-text sign-off reference vs resolvable document id) — decide before the FE builds against it.
- **OQ-e** — the FE/OpenAPI generated-types gate (`make gen-api-check`) must cover the new router; breach `state` + limit `status` vocab become FE-visible contract.
- **OQ-f** — identity-freeze UX (OD-I): a re-target is a NEW limit — state the create-new+suspend-old flow so the FE never demands a PATCH the service rightly refuses.
