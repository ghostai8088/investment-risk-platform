## Key Learnings
- **The person-level SoD is "one string-form away from decorative" at the HTTP boundary** (Fable D1): the SoD compares raw actor_id strings while `has_permission` compares the same identity through PG's case-INsensitive uuid cast — so a non-canonical form of a maker's own id passes the permission gate but ESCAPES the maker-set → self-approval. **Fix (verifier F1): canonicalize in the SERVICE/actor layer, not the router** — `LimitActor.__post_init__`/`BreachActor.__post_init__` lenient `str(uuid.UUID(x))` (non-UUID tick/test ids pass through). Self-defending; API-2b's breach SoD inherits it for free. The defeat is PG-specific (SQLite CHAR GUID is case-sensitive), so it's proven at the canonicalization UNIT level, not through a SQLite HTTP test.
- **A live-database security gate (npm audit) can flip an unchanged tree green→red** when a new advisory publishes. The disciplined response for an unreachable advisory is a **time-bound, reachability-justified allowlist that FAILS CLOSED** (expired exception → CI red; unlisted advisory → red; JSON-format drift → red) — a disposition, not a suppression.
- **The worker's raw `--tenant` string is the SSO-1 bug's SECOND instance, silent-FAIL-OPEN** (Fable OQ-a): a non-canonical tenant id makes RLS hide every row → the tick fires/evaluates/escalates NOTHING while printing a normal `fired=0` summary. For a monitoring control, silent-empty IS fail-open. Any code path arming a tenant RLS GUC from an external string must `str(uuid.UUID(...))` it first.
- **A state-conflict must map to 409, not 422** (verifier MED-1): approve-a-non-DRAFT / double-approve-loser / suspend-a-DRAFT are conflicts, uniform with the SoD 409; keep 403 meaning ONLY "missing permission". Introduced `LimitStateError(LimitError)`.
- **`map_refusal` walks the exception MRO** — register the SoD subclass as its OWN key or it collapses to the `LimitError`→422 base (verifier B1); reserve the exact-type `raise_mapped_write` for `IntegrityError` only.
- **`extra="forbid"` on request DTOs** turns a smuggled `status`/typo into a loud 422 instead of a silent no-op; **string-in/string-out decimals** are precision-safe (a JS number loses precision); a malformed decimal must fail-closed to a clean 422 (`_threshold()` guards `InvalidOperation`), never a 500.
- **≥3-finder convergence = CONFIRMED-blocking**, and **"can this control pass vacuously / be bypassed via an alternate lifecycle path or a co-submitted field?"** are now standing review angles (both MG-2 and MG-3 HIGHs were this class).
